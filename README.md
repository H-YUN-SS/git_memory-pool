# 高性能内存池 (High Performance Memory Pool)

一个基于C++实现的高性能内存池项目，提供两个版本的实现，适用于不同的应用场景。

## 项目简介

本项目实现了高效的内存管理机制，通过预先分配和重用内存块来减少频繁的内存分配/释放操作带来的性能开销。项目包含两个版本：

- **v1**: 基础内存池实现（C++11），适合单线程或简单场景
- **v2**: 三层架构高性能内存池（C++17），支持高并发多线程环境

## 特性

### v1 版本特性
- 64个固定大小内存池（8B ~ 512B）
- 哈希桶映射快速定位
- 简单高效的内存管理
- C++11标准实现

### v2 版本特性
- **三层架构设计**
  - ThreadCache: 线程本地无锁缓存
  - CentralCache: 中心缓存，批量分配
  - PageCache: 页缓存，Span管理
- **高性能优化**
  - 无锁设计提升并发性能
  - Span合并减少内存碎片
  - 延迟归还策略优化系统调用
- **完整的测试套件**
  - 单元测试
  - 性能测试
- C++17标准实现

## 使用方法

### v1 基础版本

```cpp
#include "MemoryPool.h"

int main() {
    // 创建内存池
    MemoryPool pool;
    
    // 分配内存
    void* ptr = pool.Allocate(128);  // 分配128字节
    
    // 使用内存...
    
    // 释放内存
    pool.Deallocate(ptr);
    
    return 0;
}
```

### v2 高级版本

```cpp
#include "MemoryPool.h"

int main() {
    // 使用静态接口
    void* ptr = MemoryPool::Allocate(256);  // 分配256字节
    
    // 使用内存...
    
    // 释放内存
    MemoryPool::Deallocate(ptr);
    
    return 0;
}
```

## 性能特点

### v1 版本
- 适合小对象频繁分配场景
- 内存分配时间复杂度接近 O(1)
- 内存利用率高，碎片少

### v2 版本
- **多线程性能优异**: 线程本地缓存避免锁竞争
- **系统调用少**: 批量分配和延迟归还策略
- **内存碎片少**: Span合并机制
- **扩展性好**: 三层架构易于优化和扩展

## 技术实现

### 核心技术
- **原子操作**: 使用 std::atomic 实现无锁编程
- **线程本地存储**: thread_local 关键字实现线程隔离
- **系统调用**: mmap/unmap 管理大块内存
- **内存对齐**: 提高内存访问效率

### 内存管理策略
1. **固定大小内存块**: 减少内存碎片
2. **哈希桶映射**: 快速定位合适大小的内存池
3. **批量分配**: 减少系统调用次数
4. **延迟归还**: 提高内存重用率

## 性能对比

### v2 版本性能测试结果

测试分为【单线程小对象、4线程并发、混合大小分配】三类，对比原生 new/delete：

| 测试场景 | 内存池耗时 | 原生耗时 | 性能提升 |
|---------|-----------|---------|---------|
| 单线程5w次小对象分配 | 9.323ms | 10.693ms | ↑14.7% |
| 4线程合计10w次分配 | 22.183ms | 20.371ms | - |
| 10w次混合尺寸分配 | 6.345ms | 12.154ms | ↑47.8% |

**测试总结：**
- **常规业务混合内存场景**：性能提升接近50%，是内存池落地收益最高的场景
- **多线程场景**：短时小并发时原生小幅占优，但多线程扩容后内存池无锁架构优势会持续放大
- **单线程小对象场景**：性能提升约15%，适合频繁小对象分配的业务

### v2 版本适用于:

- 对性能要求极高的场景

## 注意事项

1. v2版本需要C++17支持，请确保编译器版本符合要求
2. 在多线程环境下，推荐使用v2版本以获得最佳性能
3. 对于超大对象（>512KB），直接使用系统内存分配
4. 内存池在程序结束时自动释放所有资源
